## Plan-76 R1 保留季度与公共资源

该批源码起点为 `7fa9183479b465020d34114199a71431ac3054fb`，完成于 `fda1c14`。[Plan-76 R1 · Issue #4](https://github.com/MyKr-YSteinsK/bangumi-side-b/issues/4)

用 0.9.2 源码、合成四月与七月、loopback 和临时 Git remote 复现。四月 facts/covers 受阻且无 REVIEW，七月健康。无公共资源改动时构建写入为零。随后逐次改 CSS、主脚本与 PWA 脚本，三个文件都保持原大小，保留清单仍记录原 SHA-256。第一次 CSS 改动把同为 95,975 字节的文件从摘要 `d2f10cbf…` 换成 `de9dc130…`，旧页仍带原查询参数，文件路径供给的是新字节。旧浏览器已经完整下载的四月能断网打开，新浏览器首次下载四月得到“资源哈希校验失败”和 `INCOMPLETE`。当时 `status`、`doctor --local`、候选树与 build state 对照均通过。资料审计只认七月为可发布事实，仍未阻拦通过保留树公开四月，实际 prepare/publish 都接受了该候选并写入临时远端。

在原路径上拒绝冲突可以保护上次树，但会挡住健康季度。重渲染保留页需要从可信的历史投影恢复页面和全部资源关系，并使旧页依赖新脚本。实现选择为三个公共文件使用真实 SHA-256 路径，复用每季已经验证过的页面和清单。当同一文件仍被引用时保留，最后一个引用消失时由原 writer 回收。原封面仍使用现有物理路径，如旧季度与新事实需要不同字节，构建会报告季度与路径并保留现场。[静态构建](../static-build.md#shared-resources-across-builds)

本机验证使用 Windows、Python 3.14.6、SQLite 3.50.4、Pillow 11.3.0、libwebp 1.5.0 和 Playwright 1.61.0。Ruff、454 项非浏览器、21 项 Chromium 发布冒烟、3 项新增浏览器检查均通过。构建和恢复回归覆盖文件缺损、写入中断、重复恢复、零写入与 mtime。浏览器回归另注入响应损坏、网络暂停和 `QuotaExceededError`，核对旧包保留、续传与缓存复用。

| 丢失七月 JSON；build state 损坏 | 前者定向写 1 项，读取原封面 0 次。后者全量重写 24 项。两次恢复的站点均与此前正确树字节一致。 |

错误清单的故障注入显示，基线全量会接受错误 `data_revision`，全量和增量都可能接受错误包 `revision`。现行两个构建路径均拒绝这些不一致，新增回归也检查了错误的资源哈希、大小、非本地路径和旧站点保护。[构建回归](../../tests/test_site_builder.py)

Plan-73 的备份、状态提交和写锁继续生效。独立子进程的中断测试覆盖文件替换前后、状态提交前后、恢复中再次中断及其间用户改动造成的第三种内容冲突。Windows 文件占用释放后可重建。临时远端验证 prepare 的嵌套 build、候选同长度改写与增删、过期状态和源码/远端绑定拒绝。[中断回归](../../tests/test_write_recovery.py) · [发布回归](../../tests/test_release_workflow.py)

本机 Ruff、447 项非浏览器测试和 21 项 Chromium release smoke 均通过。

升级为补丁版的原因是季度导航、保留季度恢复及错误清单处理发生可观察变化。在同一候选源码上恢复正式版本和更新日志后，15 步均只额外改变 `settings/index.html`、`data/pwa-shell.json` 和 `sw.js` 的字节。生产数据与已发布页面见原观察。该批发现的公共静态资源跨代冲突已在 Plan-76 R1 处理。

## Plan-74 同步准入与季度写入

该批源码起点为 `4fbda787966a0f9d1175b6acb86c38136037abb9`，完成于 `50f1db6`。[Plan-74 · Issue #2](https://github.com/MyKr-YSteinsK/bangumi-side-b/issues/2)

## 当前能力与风险

- 同步支持单季度和闭区间、阶段耗时、结构化报告及 REVIEW。可按用户确认分别裁决季度与日本性。本机站点构建保留增量产物状态及失败回滚。
- Quarter 浏览 TV 首播/续播与剧场版，Archive 支持季度、年份、范围和本机离线检索。已应用的查询和精确 occurrence 可通过 URL 恢复。本机跨季度模式只读取已验证活动季度。移动端详情、筛选 draft/apply 与浏览器历史是回归重点。
- 已验证季度可先显示保存内容，以 `data_revision` 检查更新并保持 per-client 选择。Root 仍先获取 archive index 才选目标季度。历史模拟弱网中这一步有可见成本。真实 Safari、已安装 PWA、当前生产网络以及 Pages 运行在本轮没有实测。
- 默认 CI 与深度 Chromium/WebKit 分层。历史 WebKit Archive 导航曾出现等待超时，证据条件见 [历史摘要](../archive/README.md)。页面、搜索、下载、缓存和构建模块的升级以回归行为和实测数据为准。
