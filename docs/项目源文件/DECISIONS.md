# Bangumi Side B 长期决定

编号沿用原项目。规则执行细节由代码、受控配置和 [运行手册](RUNBOOK.md) 中的专项合同维护。

| 决定 | 现行含义 |
| --- | --- |
| **D-001** 收录范围 | Japanese Anime 中的 TV 与普通院线剧场版。WEB、OVA、OAD 和人员相关内容留在当前产品范围外。 |
| **D-002** 确定性事实 | 准入和投影依靠结构化证据与明确规则。AI 可找证据、解释冲突或协助人工复核；只有用户明确决定才写入支持的人工配置。 |
| **D-003** 事实来源 | Browse/Search 负责发现。写入事实前以 canonical detail 和适用确定性规则确认标题、日期、媒体、集数、来源、标签和图片。 |
| **D-004** 季度 appearance | 作品身份与季度条目分离。TV 可在多个季度出现，保持一个 premiere 和后续 continuing。Movie 只有 premiere。 |
| **D-005** 正式站点 | 通过 SQLite、封面、受控配置与静态源资源离线生成一个 `dist/site`。本地预览与 Pages 使用同一棵树。 |
| **D-006** 在线优先与 PWA | 同一站点可以直接在线使用。最小离线应用壳、runtime cache 和校验完整的季度包分别承担不同职责。用户明确选择离线范围。 |
| **D-007** 移动浏览 | 详情使用全宽单栏工作区，列表在后台保持位置。筛选编辑保留草稿，应用后更新列表。关闭、系统返回或取消丢弃未应用的草稿。 |
| **D-008** 产品名称 | PWA 短名是 `Side B`。 |
| **D-009** 局部动效 | 局部结果动效遵守 reduced-motion。历史 iOS Safari 与 standalone 曾出现全屏闪黑。重新评估根级或跨文档 View Transition 需要验证收益并复验该问题。 |
| **D-010** 发布身份 | 应用 SemVer 来自源码和具体 changelog，Pages 批次号来自发布元数据。源码 commit、候选 tree 与实际 Pages commit 单独追溯。 |
| **D-011** 历史资料 | 旧 Plan/Handoff、上下文导出和历史基线用于追溯，当前指令和事实从仓库有效源恢复。 |
| **D-012** 证据不足与事实冲突 | 日本性缺失按领域规则判断。当前指定的 `information-insufficient` 类可触发自动排除缓存。影响收录的事实冲突进入 REVIEW，由人工裁决。 |
| **D-013** 仓库独立 | 延续独立仓库。若以后与外部工作流集成，先证明需求，再确定独立兼容的包或接口边界。 |
| **D-014** 两类更新 | 由用户显式刷新应用壳。季度数据/包的更新维持校验和完整代际，自动维护限于用户已有下载范围。 |
| **D-015** CI 风险分层 | 默认 Linux/Windows 非浏览器测试与 Chromium release smoke。根据影响选择手动深度 Chromium/WebKit 回归和必要真机验收。 |
| **D-016** 正式源码交付 | 有 tracked 变更的获批准 Plan 在必要验证通过且源提交完成后普通推送一次，确认实际远端。已授权的 live 验证、review、audit 和回归在推送前完成。范围内无 tracked 改动时无需 commit/push。 |
| **D-017** 自然季度与 TV 窄例外 | Movie 归 canonical 首映日的自然季度。TV 在目标季度开始前 1–7 天首播时才可能例外。1–2 集短篇仍归自然季度。长篇需多周连续正片证据、明确目标季度信号且无结构化冲突。季度标签仅辅助。未决 `TV_QUARTER_BOUNDARY` 进入 REVIEW，不能触发自动排除。 |
| **D-018** 判相关性再判日本性 | 有 canonical 媒体和日期时，先决定目标季度相关性，再判日本范围。精确地区证据支持兼容合拍，独立来源冲突保留。受可靠日期和低评分支配时记录 `outcome_dominated_low_rating`，保留原日本性证据。剩余人工日本性判断走独立 `bgmb classify` 和 `japanese-overrides.toml`。 |
| **D-019** 自动排除生命周期 | `excluded_subject_ids` 是人工排除。`auto_excluded_subject_ids` 是可重评估的自动规则结果。主动刷新季度时，只有重新发现的作品才用 fresh canonical evidence 重评估。人工排除和仍影响收录的 REVIEW 继续有效。 |
| **D-020** 剧场分篇身份 | Plan-45 记录 `604330`、`604331` 为各自独立的剧场分篇，分别应用本身的准入证据。`582501` 是 WEB 汇总条目，不借用它的评分。来源见旧决定正文或 [历史摘要](../archive/README.md)。 |
| **D-021** 特殊放映场所 | `platform=剧场版` 仍需通过场所门。`其他` 中精确值 `游乐设施电影`、`プラネタリウム上映作品` 硬拒绝；仅可人工确认的个案走人工排除。`法国` 是精确负向地区，`欧美` 保持宽泛。旧自动项被 fresh canonical 硬拒绝取代时移除并报告 `auto_reconciled`。 |
| **D-022** 已验证季度优先可用 | 同源导航先保留用户选中的在线版本 pin。其余经过哈希验证且无 staging 的 `COMPLETE` 季度可先显示保存页面。后台按 `data_revision` 检查新数据，用户可显式查看验证后的在线版本。该动作不会把在线版本提升为离线 active 包，检查失败时旧包继续可用。 |
| **D-023** 单作品低评分豁免 | `501729` 只豁免 `low_rating_count` 与 `outcome_dominated_low_rating`，继续遵守范围、REVIEW、人工排除和不足证据规则。是否收录以另行授权的真实验证为准。 |
| **D-024** 现有项目按孵化器续接 | 有效文件集中在 `docs/项目源文件/`。日常 Codex Native 直接维护，GPT Project Main 负责探索、方案审查和经授权的正式 Issue 交接。保留版本、任务编号和历史证据入口。退役文档和过期派生物进入本机待清理区。接手时冻结升级候选；后续选择见 D-025。 |
| **D-025** 工程修复优先（2026-11-24） | 用户接受同步与准入、构建与发布验证、浏览体验、弱网与 PWA、测试维护五个方向。本批实施本机中断恢复与双写修复；其余按批细化。取消整个私人浏览工作区与维护工具方向，含收藏、观看进度、常用条件、维护面板、操作对比页、诊断中心、恢复向导、账户、云同步及服务端候选。取消 WEB、OVA、OAD 收录扩展。分批顺序见 [Plan-73 · Issue #1](https://github.com/MyKr-YSteinsK/bangumi-side-b/issues/1)，正式执行从经授权 Issue 交接。 |
| **D-026** 公共资源跨代与离线协议 v2（2026-11-25） | Plan-76 R1 允许以一次性离线重建和重新下载换取简单的新版契约。CSS、主脚本和 PWA 脚本按真实 SHA-256 命名。保留季度使用上次可核验的页面、事实和依赖，健康季度可更新。v2 清单、worker 和浏览器缓存使用独立名称。旧缓存留给用户管理。SQLite schema 2、已校验封面与人工裁决保全。新版内部继续按 D-006、D-014、D-022 保证可验证的离线更新和故障回退。后续不兼容改动各按对应 Plan 决定。[授权与取舍](https://github.com/MyKr-YSteinsK/bangumi-side-b/issues/4) |
